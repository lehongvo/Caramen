# Problem 0709: 4Sum

- **Difficulty:** Medium
- **Topics:** sorting + nested two pointers, skipping duplicates, `i64` to avoid overflow
- **Source:** [LeetCode 18. 4Sum](https://leetcode.com/problems/4sum/)

## Problem

Given a vector `nums` and an integer `target`, return every **distinct** quadruplet
`[a, b, c, d]` of values taken from four different positions such that
`a + b + c + d == target`.

Quadruplets with the same values (in any order) count once. The quadruplets, and the values
inside each one, may be returned in any order.

Implement `Solution::four_sum(nums: Vec<i32>, target: i32) -> Vec<Vec<i32>>`.

## Examples

```text
Input:  nums = [1, 0, -1, 0, -2, 2], target = 0
Output: [[-2, -1, 1, 2], [-2, 0, 0, 2], [-1, 0, 0, 1]]

Input:  nums = [2, 2, 2, 2, 2], target = 8
Output: [[2, 2, 2, 2]]
```

## Constraints

- `1 <= nums.len() <= 200`
- `-10^9 <= nums[i] <= 10^9`
- `-10^9 <= target <= 10^9`

## Hints

1. Fix the first **two** values with two nested loops, then run the two-pointer scan from 3Sum.
2. Four values of `10^9` add up to `4 * 10^9`, which does not fit in `i32`.

## Answer

<details>
<summary>Show the answer</summary>

**Idea:** sorting + nested two pointers: sort. Fix `i`, then `j > i`, and look for pairs in
`nums[j + 1..]` with a two-pointer scan, exactly as in 3Sum. Duplicates are skipped at every
level: a value of `i` equal to the previous `i`, a value of `j` equal to the previous `j` (in the
same `i` loop), and equal `lo` values after a match.

All sums are computed in `i64`: in `i32`, four values of `10^9` overflow (a panic in debug
builds, a silently wrong wrap-around in release builds).

**Complexity:** `O(n^3)` time, `O(1)` extra space besides the output.

**Rust concepts:**
- `i64::from(x)` widens losslessly; sums are compared as `i64` against `i64::from(target)`.
- Rust checks integer overflow in debug builds, so a test with huge values catches the bug that
  C or Java would silently hide.

```rust
use std::cmp::Ordering;

pub struct Solution;

impl Solution {
    pub fn four_sum(nums: Vec<i32>, target: i32) -> Vec<Vec<i32>> {
        let mut nums = nums;
        nums.sort_unstable();
        let n = nums.len();
        let target = i64::from(target);
        let mut result = Vec::new();
        for i in 0..n {
            if i > 0 && nums[i] == nums[i - 1] {
                continue;
            }
            for j in i + 1..n {
                if j > i + 1 && nums[j] == nums[j - 1] {
                    continue;
                }
                let base = i64::from(nums[i]) + i64::from(nums[j]);
                let (mut lo, mut hi) = (j + 1, n - 1);
                while lo < hi {
                    let sum = base + i64::from(nums[lo]) + i64::from(nums[hi]);
                    match sum.cmp(&target) {
                        Ordering::Less => lo += 1,
                        Ordering::Greater => hi -= 1,
                        Ordering::Equal => {
                            result.push(vec![nums[i], nums[j], nums[lo], nums[hi]]);
                            lo += 1;
                            hi -= 1;
                            while lo < hi && nums[lo] == nums[lo - 1] {
                                lo += 1;
                            }
                        }
                    }
                }
            }
        }
        result
    }
}
```
